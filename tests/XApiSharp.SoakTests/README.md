# XApiSharp.SoakTests

Local, long-running resource checks (spec section 19.5) - **not part of the default suite.**

Every test here is skipped unless `X_RUN_SOAK_TESTS=1` is set (see `SoakFactAttribute`); CI never
sets it, the same way `XApiSharp.IntegrationTests` is excluded from normal runs. No real X API
access is involved - both tests run entirely against synthetic, in-process data (a generated
NDJSON stream, a generated byte payload), so there's no network or credential dependency; they're
opt-in because they push real data volume through the real code paths (hundreds of thousands of
events, hundreds of megabytes), which takes real time and isn't something every `dotnet test` run
should pay for.

## What's checked

- `StreamingSoakTests` - 500,000 NDJSON events (with periodic blank-line heartbeats) through
  `StreamingClient.StreamPostsSampleAsync`, verifying peak managed memory stays a small, bounded
  per-event overhead rather than growing proportionally with event count (STREAM-04: no unbounded
  accumulation), that stopping the enumeration closes the underlying connection/stream (STREAM-12),
  and that exactly one connection was opened for the whole run (no silent reconnect loop).
- `MediaUploadSoakTests` - a 200 MiB synthetic upload through `MediaClient.UploadFromStreamAsync`
  with 2 MiB chunks, verifying peak managed memory stays within a small multiple of one chunk
  rather than scaling with the total transfer size (MEDIA-01: never read the whole file into
  memory), checked under an actual multi-hundred-megabyte transfer instead of only by code
  inspection.

Both record their parameters (event/byte counts, chunk/message size limits) and measured peak
managed-memory/working-set figures to test output. Per spec 19.5 ("don't conclude no leak from one
RSS figure alone - check live objects/resources after completion"): peak memory is sampled with a
**forced** GC collection at each sample point, not a raw `GC.GetTotalMemory(false)` reading - the
unforced form counts allocated-but-not-yet-collected garbage as if it were live, which overstates
"peak" in a tight loop that outruns the collector. See `docs/coverage.md` for the last recorded
run's actual numbers, SDK version, and date.

## Running

```bash
X_RUN_SOAK_TESTS=1 dotnet test tests/XApiSharp.SoakTests
```
